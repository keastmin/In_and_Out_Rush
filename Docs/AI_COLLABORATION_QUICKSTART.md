# ProjectIO AI 협업 기능 작업 빠른 시작

두 작업자는 기능 목표를 자연어로 요청하고 예약 내용을 한 번 승인한다. Git 동기화, Active 예약 공개와 구현 직전 재확인은 에이전트가 담당한다.

## 자동 작업 흐름

```text
자연어 기능 요청
→ Fetch와 안전한 Pull 시도
→ 기존 Active 예약과 관련 기능 확인
→ Active 예약 문서만 작성
→ 다시 Fetch와 안전한 Pull 시도
→ 새 변경과 예약 충돌 검사
→ 사용자 승인 대기
→ Active 문서만 Commit·Push
→ 원격 예약 존재 확인
→ 마지막 Fetch와 안전한 Pull 시도
→ 새 충돌이 없으면 구현
→ 검증·기능 문서 갱신·Completed 이동
```

## 작업자가 할 일

- 기능 목표와 기대 동작을 알려준다.
- 에이전트가 보여준 수정 예정 파일, Scene·Prefab과 공용 연결부 예약을 확인한다.
- 문제가 없으면 예약 공개와 구현 진행을 한 번 승인한다.
- 구현 후 필요한 Unity 플레이 테스트와 최종 결과를 확인한다.
- 구현 결과의 최종 Commit·Push가 필요하면 별도로 요청한다.

정해진 요청 양식은 없다. 기존 기능을 유지할지 교체할지, Scene·Prefab 변경 허용 여부와 Host·Client 기대 동작을 함께 알려주면 추측을 줄일 수 있다.

## 에이전트가 멈추는 경우

- 작업 트리에 기존 미커밋 변경이 있음
- 원격 Fetch 또는 fast-forward Pull 실패
- 로컬 commit이 Push되지 않았거나 브랜치가 분기됨
- 다른 Active 작업과 파일·Asset·공용 계약이 겹침
- Active 문서 외의 파일이 예약 Commit에 포함됨
- 예약 Push 또는 원격 예약 확인 실패

에이전트는 이 문제를 자동 stash, reset, merge commit 또는 강제 Push로 우회하지 않는다.

## 협업 전제

두 작업자는 Active 문서가 보이는 동일한 공용 upstream 브랜치를 사용해야 한다. 서로 다른 기능 브랜치에만 Active 문서를 Push하면 상대방이 예약을 볼 수 없으므로 이 자동화만으로 충돌을 막을 수 없다.
