# ADR-0002 경량 기능 작업 파이프라인

Status: Accepted

Date: 2026-08-14

## 배경

Active 문서가 로컬에만 존재한 채 구현되면 상대 작업자가 예약을 볼 수 없다. 반대로 상대방 승인, 자동 Commit·Push와 반복 확인을 모두 강제하면 두 명 규모의 협업에 비해 절차가 과해진다.

## 결정

1. 모든 구현 요청은 `manage-feature-work` Skill의 동기화 확인부터 시작한다.
2. Pull할 변경이 있으면 에이전트가 알리고 작업자가 Pull한다.
3. 에이전트가 기존 Active 예약과 요청 범위의 의미상 충돌을 검사한다.
4. 충돌이 없으면 에이전트가 Active 문서를 먼저 작성한다.
5. 작업자가 Active 문서를 Commit·Push한 뒤 에이전트가 원격 존재를 확인한다.
6. 새 충돌이 없으면 상대 작업자의 승인 없이 구현한다.
7. 구현 후 에이전트가 관련 문서 갱신과 Completed 이동을 수행한다.
8. 에이전트는 자동 Commit·Push와 위험한 Git 상태 변경을 하지 않는다.

## 결과

- 작업자가 기억할 절차는 Pull과 Active 문서 Push로 제한된다.
- Active 예약의 공유 부재와 작업 전 최신 변경 누락을 방지한다.
- 충돌이 없는 작업에 상대방 승인이나 문서 검토를 요구하지 않는다.
- 원격 변경이 없을 때는 전체 프로젝트와 문서를 반복해서 읽지 않는다.
