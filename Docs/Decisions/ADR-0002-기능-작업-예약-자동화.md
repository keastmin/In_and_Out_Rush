# ADR-0002 기능 작업 예약 자동화

Status: Accepted

Date: 2026-08-14

## 배경

Active 문서 작성이 에이전트의 권장 절차에만 머물면 한 번의 요청 안에서 예약 공유 없이 구현까지 끝날 수 있다. Pull 시점과 예약 Push를 사용자가 기억하는 방식도 누락 가능성이 있다.

## 결정

1. 모든 구현 요청은 기능별 Skill보다 먼저 `manage-feature-work` Skill을 적용한다.
2. 저장소 스크립트가 Preflight, 예약 재확인, 예약 전용 Commit·Push, 구현 직전 검증을 수행한다.
3. Pull은 깨끗하고 분기되지 않은 브랜치에서 `--ff-only`로만 수행한다.
4. Active 문서 작성 후 사용자의 승인을 한 번 받고, 승인되면 예약 문서만 Commit·Push한다.
5. 원격 예약 존재와 마지막 동기화를 확인한 뒤 의미상 충돌이 없으면 구현을 계속한다.
6. 두 협업자는 예약이 보이는 동일한 공용 upstream 브랜치를 사용한다.
7. 구현 결과의 최종 Commit·Push는 예약 공개 승인과 분리한다.

## 사용량 제한

- Git 상태, commit hash와 변경 파일명은 스크립트가 처리한다.
- 원격 변경이 없으면 Project Map과 기능 문서를 다시 읽지 않는다.
- 변경이 있으면 새 Active 문서와 예약 경로에 관계된 diff만 조사한다.
- Git 파일 충돌이 아닌 의미상 충돌 판단에만 에이전트 추론을 사용한다.

## 결과

- 사용자가 Active 문서 Push를 기억하지 않아도 예약이 구현 전에 공유된다.
- 상대방의 최신 작업과 예약을 구현 직전에 다시 확인한다.
- 안전하지 않은 Git 상태에서는 자동화가 구현보다 먼저 중단된다.
- 공용 upstream을 공유하지 않으면 예약 가시성을 보장할 수 없다.
