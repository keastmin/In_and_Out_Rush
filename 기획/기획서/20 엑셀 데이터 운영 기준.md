# 엑셀 데이터 운영 기준

## 1. 두 자료의 역할

### Markdown 기획서

다음 내용을 확인하는 **기능 기준 문서**다.

- 기능의 목적
- 작동 순서
- 플레이어가 경험하는 결과
- 예외·상호작용
- 다른 기능과의 관계
- 아직 결정되지 않은 기획 범위

### Excel 데이터 테이블

다음처럼 행·열로 표현할 수 있는 **조정 데이터 원본**이다.

- 비용
- 피해량
- 확률
- 지속시간
- 재사용 시간
- 이동속도
- 배수
- 수량
- 생성량
- 웨이브 등장 시각
- 스테이지별 배치량

따라서 개발자는 **기능을 확인할 때 Markdown을 먼저 읽고, 구현값을 확인할 때 해당 Excel 시트를 확인한다.**

## 2. 단일 원본 원칙

같은 조정값은 한 곳에서만 직접 입력한다.

- 판 공통값 → `Global`
- 러너 조정값 → `Runner`
- 경제·업그레이드·상점 → `Economy`
- 타워 → `Tower`
- 속성 → `Attribute`
- 아이템 → `Item`
- 스킬 → `Skill`
- 무기 → `Weapon`
- 몬스터 → `Monster`
- 웨이브 → `Wave`
- 맵·성소 → `Map`
- 유물 → `Artifact`

집계값은 가능한 한 수식으로 참조한다.

## 3. 상태값

- `확정`: 현재 구현 기준으로 사용할 수 있다.
- `임시`: 최초 플레이 테스트용. 밸런스 조정 가능.
- `상정`: 기획 방향은 있으나 밸런스 검증 전.
- `질문 필요`: 기획자 결정이 있어야 한다.
- `추후 입력`: 기능 방향은 확정됐지만 세부 수치를 아직 작성하지 않는다.
- `보류`: 목록에는 남기지만 현재 기능으로 사용하지 않는다.

## 4. 수정 절차

1. 기능 설명과 예외를 Markdown에서 확인한다.
2. 해당 기능의 원본 시트를 확인한다.
3. 숫자만 변경하면 Excel만 수정한다.
4. 숫자 변경으로 기능 결과가 달라지면 Markdown도 함께 수정한다.
5. 미확정 항목은 질문지 답변 없이 숫자를 임의 입력하지 않는다.
6. `Validation` 시트로 총량·확률 합계·핵심 참조값을 확인한다.

## 5. 현재 데이터 테이블 구성

- `README`: 데이터 사용법과 시트 안내
- `Global`: 판 전체 공통값
- `Runner`: 러너 조작·능력치
- `Economy`: 자원·업그레이드·토큰 상점
- `Tower`: 타워 수치와 지원 효과
- `Attribute`: 속성 확률과 속성 효과
- `Item`: 아이템 수치
- `Skill`: 스킬 수치
- `Weapon`: 무기 밸런스 입력
- `Monster`: 몬스터 전투·실패 피해
- `Wave`: 이벤트 단위 웨이브 시간표
- `Map`: 스테이지·성소·배치량
- `Artifact`: 유물 조정값
- `Validation`: 데이터 정합성 검사
- `ChangeLog`: 이번 개편에서 변경된 데이터와 근거

## 6. 질문지와의 관계

질문지의 답변은 먼저 Markdown 기능 설명에 반영하고, 수치로 관리할 수 있는 답변은 Excel 원본값에도 반영한다. 답변이 없는 항목은 `질문 필요` 또는 `추후 입력`으로 유지한다.
